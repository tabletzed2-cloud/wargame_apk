# Что дальше в v13.184: аудит кода и сравнение с варгеймами

> Составлено по коду `index.html` (50 754 строки), `js/*.js` (14 359 строк), `css/*.css` (1 038 строк),
> `docs/RULES.md`, `changelogs/` (106 файлов) и `test_harness/` (121 регрессия + 14 браузерных сценариев).
> Все цифры получены прогонами по репозиторию, а не на глаз.

## 0. Главное в одном абзаце

Игра выросла в очень насыщённую систему: две карты (оперативная 20×15 и тактическая по гексам),
кампания со этапами, приказы с цепочками и связью, снабжение, разведка, карточки, награды, пленные,
окружение, онлайн-матчи. Но **инфраструктура не успевает за контентом**: версия v13.184 вышла с
рассинхроном маркеров сборки (я сам это внёс), 43 регрессии из 121 красные из-за одной этой строки,
а в коде живут два дубля определения функций, один из которых ломает рукопашную. Поэтому первым
этапом я бы сделал не «новую механику», а **оздоровление сборки и проверок** — иначе каждая
следующая фича будет стоить всё дороже.

## 1. Технические проблемы, найденные сейчас (по приоритету)

### 1.1. 🔴 КРИТИЧНО: маркеры сборки отстали от `APP_VERSION`

| Место | Значение |
|---|---|
| `index.html` `APP_VERSION` | **v13.184** |
| `manifest.json` `short_name` | v13.183 |
| `service-worker.js` `CACHE_NAME` / `BUILD-МАРКЕР` | wargame-v13.183 |
| `js/{data,hexmaps,templates,operational_ui,cards,map_actions,online_battles,placement,recon,weapons}.js` | v13.183 |

**Почему это не косметика.** В `service-worker.js` и в `index.html` есть самопроверка:

```js
// service-worker.js
const BUILD_MARKER = '⚡ BUILD-МАРКЕР: ' + CACHE_VERSION;   // CACHE_NAME → v13.183
const MARKED_ASSETS = [ './index.html' → APP_VERSION v13.183, './js/data.js' → v13.183, ... ];
// при несовпадении — throw → установка SW отменяется, кэш удаляется
```

```js
// index.html
const expected = BUILD_MARKER_PREFIX + ' ' + APP_VERSION;   // v13.184
BUILD_MARKED_MODULES = ['js/data.js','js/hexmaps.js','js/templates.js','js/operational_ui.js'];
// не совпало → forceDeepUpdate(): unregister SW, чистка ВСЕХ кэшей, reload
```

То есть на v13.184 должно происходить вот что: SW не устанавливается (кэш пустой), затем приложение
видит «устаревшие файлы», снимает регистрацию SW, чистит кэши и перезагружается с `?_build=…`.
В итоге **офлайн-режим и PWA-установка на этой версии фактически отключены**, а каждая загрузка —
глубокая переустановка. Плюс `regression_v13070.js` (специально написанный против этого класса
багов в v13.070) снова красный четырьмя проверками.

**Что делать:** один скрипт `tools/bump_version.py <vX.YYZ>`, который правит `APP_VERSION`,
`manifest.json`, `CACHE_NAME`, `BUILD-МАРКЕР` во всех модулях, и вызов его в чек-листе релиза
(в `docs/RULES.md` §1 пункт 8 это уже написано словами — нужна автоматика).

### 1.2. 🔴 Дубль определения `tacticalSquadHexPosition` ломает рукопашную

В `index.html` функция объявлена **дважды** в одном и том же `<script>`:

* строка ~17276 — «полная» версия, возвращает `{key, col, row, isEnemy, idx}` и умеет работать по `hexPos`;
* строка ~22871 — короткая версия, возвращает результат `getBattleSquadHex(...)` **без `isEnemy` и без `idx`**.

Так как это одна область видимости, действует **последняя**. Проверено в изолированной песочнице:

```
результат последнего определения: {"col":5,"row":5,"key":"5,5"}
есть isEnemy: false
```

А на `isEnemy`/`idx` держится рукопашная:

```js
// index.html ~17388, tacticalSquadsInSameHex
const pos = tacticalSquadHexPosition(squad);
const opponents = pos.isEnemy ? players : enemies;   // undefined → всегда enemies
out.push({ squad: other, idx, isEnemy: !pos.isEnemy });  // isEnemy всегда true
```

и потребители `resolveTacticalMeleesForTurn` (~23268) и `tacticalAutoEngageMelee` (~17472)
фильтруют контакты по `c.isEnemy`. Последствие: для **своего** отряда в переборе «противников»
окажутся снова свои же, а метка `isEnemy` всегда `true`. Ошибки JS при этом нет — просто
рукопашная начинает работать по неверной выборке.

То же самое, но безвредно: `useAdrenaline` объявлена дважды (20601 и 25116) с идентичным телом —
это чистая копипаста, которую надо свести к одной.

**Что делать:** удалить короткую версию и оставить полную; `useAdrenaline` — оставить одну;
добавить в `checkhtml.js` проверку «нет двух `function` с одним именем в одной области».

## 2. Игровые механики: чего не хватает

### 2.1. 🔴 Нет противника, который действует сам (в соло)

Это, по-моему, **самый большой пробел как игры**, а не как кода.

Что есть: в тактическом бою фаза «противника» — это **ручной режим**. Игрок выделяет вражеский
отряд (`selectedEnemyMoveIdx`) и **сам** двигает его и отдаёт ему «отступить»
(`retreatSelectedEnemySquad`, ~17137: «Отдать команду выбранному вражескому отряду отступить»).
На оперативной карте враг отвечает автоматическим огнём по обнаруженным целям и «восстанавливает
линию связи за N ходов» (`beginEnemyPhoneLineRepairs`), но **не двигается и не отдаёт приказы**:
поиск по коду не находит ни одной функции вида `enemyOpMove`/`enemyAiTurn`, которая меняла бы
`enemyOpUnits[].col/row` по своей инициативе.

При этом `docs/RULES.md` (§2) утверждает: «**Режимы.** Одиночная игра **против ИИ** и онлайн-матч».
Документация обещает ИИ, которого в коде нет.

**Что делать (в порядке возрастания сложности):**
1. **Скриптовые «доктрины» вместо ИИ** — самый дешёвый и самый «варгеймовый» путь:
   у каждого вражеского юнита в сценарии задаётся поведение (`hold` / `counterattack` /
   `fallback_line` / `ambush`), и на границе оперативного хода он двигается по простым правилам
   (держать гекс, контратаковать при потере окопа, отходить при потере 50 % состава).
   Уже есть похожая инфраструктура: `unit.behavior` у своих (`engage`/`hold`/`assault`).
2. **Тактический «оппонент-скрипт»** — на фазе врага автоматически: ближайший к цели отряд идёт
   по пути, стреляет по правилам, отступает при низком духе. Даже без поиска это сильно оживит бой.
3. Полноценный ИИ (оценка позиции, приоритеты целей) — уже после 1–2, когда есть чем мерить.

### 2.2. 🟠 Нет очков победы на тактической карте

Условия конца боя сейчас: «уничтожить/обратить в бегство **всех** противников» либо
`finishBattleByNumericalSuperiority` (двукратный перевес). Плюс `battle.result = victory/defeat`
по факту зачистки. Ключевых гексов, зон выхода, таймера боя — нет (поиск `exit zone`/`victory point`
по логике боя пуст).

Из-за этого:
* бой всегда «до последнего солдата» — а в реальных варгеймах (ASL, Combat Mission, Battle Academy)
  победа чаще по **удержанию объектов** и **стоимости потерь**;
* сценарий не может быть «задержать на 5 раундов и отойти»;
* оборона не имеет смысла, кроме как перебить всех.

**Что делать:** ввести `battle.objectives = [{hex, vp, kind:'hold'|'capture'}]` и считать результат
по VP при истечении лимита раундов, оставив «полное уничтожение» как досрочную победу.
Инфраструктура целей уже есть на оперативном уровне (`campaignObjectiveDefinitions`,
`renderCampaignObjectivesPanel`) — на тактический её надо продублировать в упрощённом виде.

### 2.3. 🟠 Реакции: нет «сторожащего» огня (overwatch)

`grep` по `overwatch`/`opportunity` в игровой логике ничего не даёт (совпадения — только
`bicycleBlitzOpportunityUnitName`). Есть «ответный огонь» для приказа «закрепиться» на **оперативной**
карте (`holdFireDistance`, 1 гекс) — но в тактическом бою отряд, завершивший фазу, не может
выстрелить в чужой ход.

Это самый заметный «недостающий такт» для пошагового варгейма: без него нельзя «прикрыть подход»,
и вся тактика сводится к «кто первым подойдёт». В Combat Mission/Battle Academy/XCOM роль
overwatch-а — половина тактики.

**Что делать:** одно очко ОД откладывается в «сторожевой режим» с сектором (или просто
«первые N целей, вошедших в радиус»); срабатывает на перемещении врага. Уже есть готовые
кирпичи: сектора обстрела бронетехники (`drawTacticalVehicleSectorLines`, `weaponSectors`),
проверка LOS (`tacticalHasLineOfSight`) и «ручной» триггер входа в гекс
(`tacticalAutoEngageMelee`).

### 2.4. 🟠 Боеприпасы не различаются по типу

У орудий есть `penetration` по дистанции (`js/weapons.js`), но нет выбора типа боеприпаса —
бронебойный/осколочно-фугасный/дымовой. Снаряды считаются одним счётчиком `ammoOrdnance`,
гранаты — отдельно. Отсюда: нельзя «поставить дымовую завесу» снарядом, нельзя экономить
бронебойные, стреляя фугасными по пехоте.

Это классическая ось решений в варгеймах (ASL, Combat Mission, Steel Panthers), и её отсутствие
делает артиллерию «одной кнопкой».

**Что делать:** поле `shellTypes: {ap, he, smoke}` у расчёта + выбор при выстреле; расход из
разных счётчиков; smoke уже частично реализован (`tacticalSmokeBlocksSight`, дым от ампуломёта).

### 2.5. 🟡 Броня: нет «корпус в укрытии» (hull down) и дифференцированной уязвимости по курсу

Есть `armor {front, side, rear}` и стрелка курса, есть `Броня Л/Б/К` в подписи. Но нет:
* **hull down** — позиция за гребнем/бруствером (в варгеймах это ключ к танковым дуэлям);
* учёта курса цели при попадании (сейчас пробитие зависит от дистанции, но не от того,
  под каким углом стоит машина) — а это уже есть в данных! Достаточно связать `armor.*`
  с направлением выстрела.

**Что делать:** (1) попадание «в борт/корму» при выстреле с фланга относительно `facing`;
(2) флаг `hullDown` для гекса за гребнем — минус к пробитию и минус к обнаружению.

### 2.6. 🟡 Пленные — «факт», но не механика

Сейчас: сдача при духе ≤ 0 (`tacticalSurrenderUnit`), `prisonerLedger` со счётчиком
(`campaignPrisonerCount`), в карточке взвода — одна строка «🏳️ N отделений в плену» (v13.184, п.5).
Дальше — ничего: пленные не занимают место, не требуют конвоя, не влияют на снабжение,
не дают обоза/трофеев и не могут быть отбиты.

**Что делать (дёшево и в духе игры):**
1. Пленные «висят» на сдавшемся отряде как `prisoners: N` — двигаются вместе с ним, замедляют,
   требуют 1 бойца конвоя на 5 пленных;
2. при уничтожении конвоя — освобождение/возврат в строй с низким духом;
3. при выходе с карты — пополнение кампанийного счётчика и небольшой бонус к снабжению
   (трофейные патроны — уже есть `SUPPLY_*`).

### 2.7. 🟡 Нет опыта/ветеранства

`grep` по «опыт/experience/veteran» не находит системы: есть награды-карточки (`BEVE_AWARDS`,
`AIRF`-аналоги) и «ветераны колониальной службы» как карта, но **нет накопления опыта**:
отряд, переживший 5 боёв, не становится лучше. В кампании это главный источник привязанности
игрока к юнитам (Battle Brothers / XCOM / Battle Academy).

**Что делать:** счётчик `battlesSurvived` + `kills` → 3 уровня (обстрелянный/закалённый/гвардия)
с +1 к духу, +1 к обнаружению или −1 к шансу паники. Дёшево, использует существующие модификаторы.

### 2.8. 🟡 Нет зон контроля и «запирания» движения

Покидание гекса, соседнего с врагом, ничем не карается. В гексовых варгеймах (Battle for Wesnoth,
Panzer Corps, Field of Glory) ZOC — базовый инструмент: он делает фронт «липким» и мешает
просачиваться между отрядами. Сейчас обход по флангу бесплатен.

**Что делать:** выход из гекса, соседнего с боеспособным врагом, стоит +1 ОД (или требует
проверки духа). Правило в 10 строк, меняет всю тактику.

### 2.9. 🟡 Мелочи, которые заметны в игре

* **Нет отмены последнего действия** (`undo`) — в пошаговой игре с ОД это болезненно.
  Технически: снимок `actionPoints + позиции` перед действием, откат по кнопке.
* **Нет таймера/лимита раундов** в тактическом бою — бой может длиться бесконечно;
  «закончить как ничью» (`forceFinishBattleAsDraw`) — это аварийный выход, а не правило.
* **Нет сохранения «сценарий в сценарии»** — реплея/повтора хода (в `diagnostics` уже
  реконструировали бой по JSON; значит данные для реплея есть).
* **Нет обучения бою**: туториал есть для этапов кампании (`CAMPAIGN_TUTORIAL_STAGES`), но
  не для тактической карты (LOS, укрытие, рукопашная) — а именно там больше всего правил.
* **Погоды нет** (кроме ночи и освещения ракетой). Дождь/туман/грязь — дёшево через существующие
  модификаторы и хорошо работает на «местность решает».
* **Инженерных работ мало**: окопы есть (и это хорошо), но нет проволочных заграждений,
  минных полей, подрыва мостов — при том что `trenches` уже целый тип местности с лимитами.

| Что | Эта игра (v13.184) | ASL / Combat Mission | Battle Academy / Panzer Corps | Battle for Wesnoth / XCOM |
|---|---|---|---|---|
| Уровни | стратегический + тактический гекс | тактический гекс | тактический гекс | тактический гекс |
| Противник в соло | **фаза врага вручную** | ИИ | ИИ | ИИ |
| Цели победы | уничтожение всех | VP + объекты | VP + объекты + лимит ходов | объекты / выживание |
| Overwatch / реакции | **нет** | да | да | да (в XCOM) |
| Типы боеприпасов | **один счётчик** | AP/HE/дым/подкалиберные | AP/HE | разные |
| Броня по курсу / hull down | **нет** (данные есть) | да | да | — |
| ZOC / «липкий» фронт | **нет** | да | да | да |
| Опыт войск | **нет** | да (ELR) | да | да |
| Пленные | счётчик | да (ENC) | редко | — |
| Снабжение/связь | **да, очень подробно** | да (редко в игре) | нет | нет |
| Туман войны + разведка | да | да | да | да |
| Кампания | да (сценарий + этапы) | кампании-модули | да | да |

**Что у этой игры уже лучше среднего:** связь (радио/телефон/кабель/помехи), снабжение
(склады, колонны, носильщики, расход боезапаса), мораль на двух уровнях, окружение кольцом,
карточки-модификаторы, пленные как учёт, оперативная карта с зонами местности по контурам.
Это редкость — большинство варгеймов такими слоями не занимаются.

**Что бросается в глаза при переходе с любой другой игры жанра:** «противник стоит и ждёт»,
«бой до последнего», «нет подготовки к чужому ходу». Это три пункта 2.1–2.3 — они дают
наибольший прирост в ощущении игры на единицу кода.

## 4. Предлагаемый следующий этап (v13.185 → v13.187)

### Этап A. Стабилизация (v13.185) — 1 релиз, без новых механик

2. Убрать дубль `tacticalSquadHexPosition` (оставить полную версию) и `useAdrenaline`.

покрыта регрессией (контакт своего отряда с врагом в одном гексе).

### Этап B. «Противник, который играет» (v13.186)
1. `enemyDoctrine` в сценарии: `hold` / `counterattack` / `fallback` / `ambush` — 4 поведения.
2. Фаза врага в тактике автоматизируется (простой скрипт: подход к ближайшей цели, огонь, отход
   при низком духе), с возможностью «взять управление вручную» для отладки.
3. Цели боя (`battle.objectives` + VP + лимит раундов) и результат по VP.

### Этап C. Тактические решения (v13.187)
1. Overwatch (сторожевой огонь) — 1 ОД, срабатывает на входе врага в радиус.
2. Типы выстрелов (AP/HE/дым) для орудий и миномётов.
3. Курс брони + hull down.
4. ZOC: +1 ОД на выход из соседства с врагом.

### Что я бы отложил
Погода, инженерные заграждения, реплеи, полный ИИ с оценкой позиции — полезно, но это уже
полировка, когда есть автоматический противник и цели победы.
