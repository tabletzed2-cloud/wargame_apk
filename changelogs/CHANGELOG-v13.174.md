# v13.174 — Поворот окопов при планировании онлайн-приказа

## Причина и исправление

Общий CSS-запрет `#battleApp.online-player-mode button[onclick*="rotateSelectedHex"]` скрывал не только свободный редактор карты, но и кнопки поворота в редакторе черновика приказа «Окопаться». Предыдущие проверки функций вращения не проверяли вычисленные браузером стили онлайн-интерфейса.

Запрет теперь действует вне `hex-editor-mode`. В редакторе приказа доступны штатные кнопки ±60° и сброса; до выбора клетки они по-прежнему отключены. Доступ к свободному редактированию карты онлайн-игроку не открыт. Механика приказов, лимиты и момент применения черновика не изменены.

Обновлены версия приложения, BUILD-маркеры и имя offline-кэша, чтобы исправление не осталось за старым CSS.

## Проверки

- Новый `test_harness /browser_online_trench_rotate.cjs`: настоящий Chromium, production HTML/JS/CSS, мобильный viewport 420×850, online-player-mode, редактор черновика. Проверены видимость кнопки, выбор клетки настоящим кликом по canvas, ±60°, переход через 0°, сброс, вызов вращения при отрисовке загруженной текстуры, сохранение в черновике без преждевременного применения к бою, закрытие/повторное открытие и перенос угла при выполнении приказа. PASS.
- На прежнем CSS тот же браузерный тест воспроизводит ошибку: кнопка скрыта (`display:none`), ожидание видимости завершается ошибкой. После исправления тест проходит.
- `regression_v13166_trench_limit_rotate.js`: 37 PASS, 0 FAIL.
- `node --check service-worker.js`, `git diff --check`: PASS.

Запуск браузерного теста требует `playwright-core` и `@sparticuz/chromium` через NODE_PATH. На минимальной Linux-системе также нужны библиотеки NSS/NSPR (при проверке использованы библиотеки из al2023.tar.br пакета @sparticuz/chromium через LD_LIBRARY_PATH).

Проверен локальный браузер с онлайн-состоянием приложения; сеанс с удалённым соперником и физическое Android-устройство не проверялись.
