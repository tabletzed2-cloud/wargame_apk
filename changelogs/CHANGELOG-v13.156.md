# v13.156 — снабжение, ДОТ, подкрепление, десант и тактика без фризов

Шестая партия из 39 пунктов по итогам теста: пункты 6, 9, 11, 13, 16, 17, 28, 30,
33, 34, 35, 36, 37, 38. Плюс диагностика п.18 (синхронизация тактических боёв в
онлайне) — отдельным отчётом, правка будет следующей партией.

## 6. Онлайн-расстановка: штаб батальона не «уезжает» от простого клика

* Перенос юнита по клику в режиме расстановки выполняется только для **явно
  выбранного** юнита (`campaign.opPlacementExplicitIndex`): выбор в панели
  размещения (`selectPlacementUnit`) или перетаскивание фишки из трея.
* Простой клик по карте без выделения больше не переносит первый юнит из списка
  (чаще всего это был штаб батальона). Вместо этого в `#mapInfo` выводится
  подсказка и предупреждение-тост «сначала выберите юнит».
* После успешной постановки отметка снимается.

## 9. Ось сектора обстрела ДОТа — по любому кликнутому гексу

* Ось хранится как **ключ гекса-оси** (`"col,row"`), а не как одно из шести
  направлений. Угол считается через `atan2` между гексом ДОТа и выбранным
  гексом: `dotSectorAxisVector`, `dotSectorAxisHexKey`, `dotSectorAxisValid`,
  `dotSectorAxisLabel`.
* Попадание в сектор — `tacticalHexInFireSector`: `acos` от косинуса угла между
  осью и направлением на цель, допуск ±0,5° строки гекса. Ширина 360° — все
  направления; сектор не задан — все направления.
* Клик по клетке самого ДОТа осью не считается (вектор `null`), прежние сейвы с
  `e/se/sw/w/nw/ne` продолжают читаться (`TACTICAL_FIRE_SECTOR_OPTIONS`).
* Сектора на тактической карте рисуются по этой же оси.

## 11. Карточка «Санитар»: штаб взвода не спрашиваем

* Штаб выбирается автоматически: штаб своего взвода (`currentSquad.opUnitName`),
  приоритет — штаб **без** санитара, иначе первый живой; если своего взвода в
  бою нет — любой живой штаб.
* `prompt` из обработчика карточки убран, в `applyCardToPlatoon` есть резервный
  выбор любого живого штаба.

## 13. Карточка отряда бронетехники на оперативной карте

* В `showOpUnitInfoPopup` для взводов с машинами показывается строка по каждой
  машине: `<b>имя</b> — статус`, «👥 Экипаж N/M · 🎯 Расчётов/оружия · 🔫 Патроны
  · 💥 Снаряды», «🔧 Башня/Корпус/Ходовая ✅⚠️❌».
* Источники — `unit.vehicleList` и отделения с `armor`/`isVehicle`/`vehicleList`,
  без дублей.

## 16. Окоп: отдельные кнопки поворота, без смены текстуры

* Повторный клик по уже поставленному окопу **не листает текстуры** — он только
  выбирает клетку (`st.lastCell`, `map.lastEditedHex`) и подсказывает блок
  «🔄 Поворот окопа». Правки местности при этом не тратятся.
* В баннере редактора кнопка смены текстуры (`hexEditorTrenchTextureButton`)
  убрана; остались `hexEditorRotateLeftButton` (−60°), `hexEditorRotateButton`
  (+60°), `hexEditorRotateResetButton` («⟲ Исходный вид»). Убран и дубль
  `id="hexEditorRotateButton"` в общем блоке — его кнопка теперь
  `hexEditorRotateSelectedButton` (дублирующиеся id ломали поиск кнопки).

## 17 + 37. Меню «Снабжение»

* **Получателя можно выбрать**: список больше не «схлопывается» — в нём все
  живые юниты батальона (кроме взвода снабжения), а не только те, кому прямо
  сейчас не хватает боезапаса. Раньше юнит, которому уже выслали груз,
  исчезал из списка, отметка сбрасывалась, и выбрать его было нельзя.
* Отметка получателя снимается только если юнита больше нет в батальоне
  (`supplyUnitExists`), выбор не теряется при перерисовке панели.
* Выбрать можно кликом по всей строке (не только по радио-кнопке); выбранная
  строка подсвечена, внизу — «Получатель выбран: …» либо подсказка.
* **У каждого типа боеприпасов своя шкала** — патроны, гранаты, снаряды; если по
  типу нет запаса, шкала пустая с подписью «нет в наличии» (раньше строка просто
  исчезала).

## 28. Значки караванов на оперативной карте при перемещении

* Колонна снабжения больше не «телепортируется» на новый гекс: снимаются
  позиции до хода (`supplyAnimationSnapshot`), после хода значки проезжают по
  маршруту (`animateMovedSupplyConvoys`, 150 мс на гекс, перерисовка ~30 к/с).
* Отрисовка (`drawSupplyDeliveriesOnMap`) берёт промежуточные пиксели из
  `supplyAnimPixel`, поэтому плашка едет синхронно с линией маршрута.

## 30. Ампуломёты, бутылкомёты и пехота заходят на камни

* Стоимость шага в тактике для расчётов орудий/миномётов на гексе «Камни» —
  как у пехоты, 2 ОД (`getActionCost(..., 'bad')` = 4 полу-ОД). Раньше «Тяжёлая»
  стоила расчёту 3 ОД, и он не мог войти на камни.
* Кнопка движения подписана «🌋 Тяжёлая / камни».

## 33. «Навестись на цель» — клик по врагу на карте

* Кнопка «🎯 Навестись: клик по врагу на карте» включает режим
  `map.vehicleAimPick = {squadIdx}`, модальный список целей при наведении больше
  не открывается.
* Клик по гексу с обнаруженным небоевым/нейтрализованным врагом ставит цель и
  выполняет наведение (1 ОД); клик по пустому гексу — подсказка «кликните по
  обнаруженному врагу», режим остаётся включённым.

## 34. Взвод, вступивший в идущий бой, получает меню размещения

* Если фаза размещения уже завершена, но в бою появились не выставленные
  отряды, панель размещения показывает компактный блок «📍 Подкрепление в
  идущем бою»: список отрядов, полосу размещения (сторона входа подкрепления
  либо тыл), кнопки «🏷️ Разместить» и «🎲 Выставить подкрепление»
  (`placementAutoPlaceReinforcements`), а также трей для перетаскивания.
* Раньше при завершённом размещении панель просто скрывалась, и подкрепление
  оставалось вне карты без меню и подсказок.

## 35. Фризы при движении отрядов в тактике

* Шаг по маршруту больше не пишет весь сейв в localStorage и не перерисовывает
  панель: на каждом шаге перерисовывается только карта, а сохранение и полный
  `updateUI` выполняются один раз в конце маршрута.
* `spendAP` внутри шага маршрута не делает снимок отмены и не вызывает
  `updateUI`; снимок отмены теперь один на весь маршрут.

## 36. Кнопка «ИПП отряда»

* В панели дополнительных действий появилась кнопка «💗 ИПП отрядa (+2 HP всем
  раненым, 2 ОД)» — `tacticalUseIPPSquad`: 4 полу-ОД, по 2 HP каждому раненому
  бойцу отряда, один раз за бой (`ippSquadUsedBattleKey`, сбрасывается при
  переносе отряда в новый бой).
* Кнопка активна, только если у отряда есть раненые и ИПП в этом бою ещё не
  израсходован; после применения в панели остаётся строка «ИПП отряда
  использован в этом бою». Персональный ИПП бойца (`useFighterIPP`) не затронут.

## 38. Потери десанта при уничтожении БТР

* В тактике десант в подбитой машине разбирается при **любом** способе
  уничтожения, а не только при попадании в двигатель/боеукладку:
  `tacticalSquadCarrierDestroyed` + `tacticalResolveDestroyedCarriers`
  (вызывается из `updateUI`, повторный вход ничего не делает). Каждый боец
  десанта бросает D6: 1–2 — погиб, иначе высадился на гекс машины.
* На оперативной карте при уничтожении БТР с посаженным отрядом
  (`opCarrierLossDisembark`) треть бойцов гибнет, уцелевшие высаживаются на гекс
  подбитой машины; если не выжил никто — отряд помечается уничтоженным.

## 18. Онлайн: диагностика синхронизации тактических боёв (правка — частично)

Симптом из теста: два устройства, оба в бою на одном гексе — бой видит только
атакующий. Разбор кода:

* **Главная причина** — в `onlineApplyCloudBattles` был ранний выход
  `if (appData.currentBattleId) return;`: если у атакованного уже открыт **любой**
  другой бой, зеркало не создавалось вовсе (оно откладывалось «до выхода», а
  после выхода появлялось только при следующем обновлении облака). Теперь
  зеркало создаётся сразу и **тихо** (`onlineCreateMirrorBattle(e, {quiet:true})`):
  без `alert` и без подмены экрана, запись появляется в «⚔️ Текущие бои».
* Вторая причина — молчание: если снапшот оппонента не превращался в бой, в
  логе не было ни строки. Добавлен `onlineBattleMirrorBlockReason` и запись
  причины в лог **один раз на гекс** («на гексе нет моих юнитов», «в снапшоте нет
  отрядов оппонента», «у меня этот бой уже завершён», «я сейчас внутри другого
  боя»).
* Ручная диагностика: кнопка «🩺 Синхронизация боёв» в онлайновой панели
  (`onlineShowBattleSyncReport`) и `onlineBattleSyncReport()` в консоли —
  показывает роль, статус матча, свои бои, бои оппонента из облака и причины,
  по которым они не отображены.
* Остальные места проверены и оставлены как есть: отправка боя при создании
  (`onlineBattleCreated`) и по сохранению, повторная сверка после выхода из боя
  (`onlineBattlesRecheck`), согласование гекса боя по фактическому месту
  столкновения. Если после этой партии бой всё ещё не появляется у второй
  стороны — кнопка диагностики покажет точную причину.

## 39. Ретрансляция через штаб роты не мешает своим приказам

* Раньше, пока штаб роты передавал приказы своим взводам, его **собственный**
  приказ ждал доставки чужого приказа: если ретрансляция уходила посыльным на
  несколько ходов, штаб не мог ни двинуться, ни стрелять, ни закрепиться
  (в лог писалось «своё действие ждёт доставки приказов взводам»). Теперь этого
  ожидания нет — приказ штаба исполняется в том же ходу.
* Порядок внутри хода сохранён: приказы ретрансляции (`company_order`)
  исполняются **первыми**, поэтому штаб успевает передать приказы до того, как
  сам сдвинется с места и порвёт телефонные линии.
* Приказ, отданный через штаб роты, больше не снимает «огонь по готовности» у
  самого штаба: он адресован штабу только как ретранслятору. У взводов-
  получателей новый приказ «огонь по готовности» по-прежнему снимает (п.14).
