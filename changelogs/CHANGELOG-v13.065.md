## Справка (пункт 1 заявки): где задаются стартовые координаты всех юнитов

**Файл: `js/data.js` → константа `SCENARIO_START_POSITIONS`.**

Структура:

```js
const SCENARIO_START_POSITIONS = {
  valencia: {                      // сценарий
    'BeVe': {                      // фракция
      'Штаб батальона': '5,4',     // имя юнита → 'колонка,ряд' оперативной карты
      '1-й взвод (бельг.)': '5,6',
      ...
    },
    'A.I.R.F.': { ... }
  }
};
```

Рядом лежат:

* `SCENARIO_PLACEMENT_ZONES` — полигоны зон расстановки (замкнутый список гексов);
* `SCENARIO_PLACEMENT_ZONE_EXTRA_HEXES` — явные добавления к зонам (гексы, чьи
  центры лежат ровно на границе полигона).

То есть править старт юнитов нужно в **`js/data.js`**, а не в `index.html`
и не в сохранении: при пересборке батальона координаты берутся оттуда.

## 2. Рукопашная считается по фактическому гексу (пункт 7 заявки)

**Причина ошибки.** Проверка в `meleeAttack()` брала расстояние из скрытого поля
ввода «Дистанция» (`#targetDistance`, по умолчанию **5**). Поле спрятано, изменить
его из интерфейса нельзя, поэтому проверка `!== 0` не проходила **всегда** —
даже когда свой и вражеский отряд стояли в одном гексе. Игра отвечала
«Рукопашная доступна только в одном гексе (0)».

**Что сделано.** Новые функции (блок `⚡ v13.065` перед `tacticalActionAllowed`):

| Функция | Назначение |
|---|---|
| `tacticalSquadHexPosition(squad)` | реальный гекс отряда (сначала сетка карты, затем `hexPos`) |
| `tacticalSquadsDistance(a, b)` | расстояние в гексах через `hexGridDistance()`; `null`, если позиции неизвестны |
| `tacticalSquadIsAlive(squad)` | есть ли живые бойцы |
| `tacticalSquadsInSameHex(squad)` | живые противники в том же гексе (техника не считается) |
| `tacticalMeleeTarget()` | цель рукопашной: выбранная на карте/в модалке, либо противник в своём гексе |
| `tacticalEnemyHexHasFriendlies(enemy)` | свой отряд в гексе цели |
| `tacticalAutoEngageMelee(squad)` | автоматически связывает два отряда рукопашной |

`meleeAttack()` теперь:

1. определяет цель через `tacticalMeleeTarget()`;
2. считает дистанцию по карте; и только если позиции неизвестны — берёт старый
   ручной ввод;
3. при дистанции 0 фиксирует цель (`attackTargetEnemyIdx`) и ставит отметку
   рукопашной; иначе пишет фактическую дистанцию: `Рукопашная доступна только
   в одном гексе (сейчас: 3).`

**Запрет стрельбы по своим (вторая половина пункта 7).**

* В `js/map_actions.js` (`mapActionEvalTarget`) добавлена проверка: если в гексе
  цели стоит свой живой отряд (не сам стрелок) — действие недоступно,
  причина `в гексе свои — бить нельзя`. Касается всех действий, кроме рукопашной.
* В `executeAttack()` (подтверждение в модалке выбора цели) — тот же запрет:
  окно закрывается, выводится `⛔ В гексе цели стоит свой отряд «…» — стрелять
  нельзя. Только рукопашная.`

## 3. Рукопашная начинается сама (пункт 6 заявки)

При перемещении **своего** отряда и при перемещении **отряда противника**
(`js/index.html`, обработчики клика по карте в режиме `move`) после постановки
на новый гекс вызывается `tacticalAutoEngageMelee()`:

* если в гексе живой враг (и это не техника) — оба отряда получают
  `meleeOpponentName` друг на друга, в лог уходит
  `⚔️ Рукопашная! «…» и «…» сошлись в гексе X,Y. Стрелять по этому гексу нельзя —
  только рукопашная.`;
* информационная строка под картой дополняется красной пометкой
  `⚔️ Рукопашный бой с отрядом «…»!`;
* для своего отряда цель сразу выбирается — кнопка «⚔️ Рукопашная» работает без
  повторного выбора цели;
* повторный вызов не перезаключает уже идущий бой.

Поскольку участники рукопашной уже защищены от сторонней стрельбы
(`tacticalIsMeleeEngaged`), запрет из пункта 2 включается автоматически.

## 4. В тактическом бою нет «условных» карт (пункт 8 заявки)

Информационные карты (`informational: true` — «Упрямство», «Велоблиц»,
«Горное пончо», «Талреп-якорь», «Бюрократия», «Мародёрство» и др.) и карты с
пустым/условным эффектом (`effect: 'Условная'`) не дают движку никакого эффекта —
в бою они занимали слот и вводили в заблуждение.

* Новый `isCardPlayableInTacticalBattle(card)`: отсекает `informational`,
  пустой эффект и эффекты-заглушки (`Условная`, `Информационная`, `-`).
* Вкладка «🃏 Карточки» в бою показывает только карты с реальным эффектом
  (`filterCardsPlayableInBattle`); штрафные карты по-прежнему видны, но не
  выбираются вручную — они выдаются за 4-ю бонусную.
* `activateSelectedCampaignCards()` дополнительно проверяет каждую выбранную
  карту и не даст подтвердить «условную».

## 5. Карта-дебафф обводится красным (пункт 9 заявки)

* Панель боя «🃏 Карты подразделения» (`updateActiveCardsBattle`): бонус —
  зелёная рамка `#2ecc71`, **дебафф — красная рамка `#e74c3c` на тёмно-красном
  фоне `#3a1e1e`**, перед названием стоит `▼`, в подсказке — префикс
  `[ДЕБАФФ]`.
* Список активных карт (`renderActiveEffects`): у карт с `type === 'negative'`
  рамка `2px solid #e74c3c` и фон `#3a1e1e`.
* Сама механика «4-я бонусная карта = 1 случайный дебафф» (`bonusCount === 4`
  → `getRandomNegativeCardForUnit`) оставлена как есть — она работала; теперь
  дебафф визуально отличается от бонуса, и его нельзя перепутать с бонусной
  картой.

## 6. Замена уже загруженного шаблона карты (пункт 4 заявки)

Раньше: `📥 Импорт карт` **полностью заменял** список шаблонов файлом (все
остальные шаблоны пропадали), а `💾 Сохранить текущую карту как шаблон` всегда
добавлял **новый** шаблон — с тем же именем появлялась вторая копия, и визуально
«ничего не менялось».

Теперь:

* **Сохранение с существующим именем** → вопрос
  `Шаблон «…» уже есть. Заменить его текущей картой?` → шаблон обновляется
  (второй копии нет), в логе — `Шаблон карты «…» обновлён (гексов: N)`.
* **Импорт файла** больше не стирает существующие шаблоны: совпадения по имени
  заменяются (с подтверждением и списком имён), новые — добавляются.
* Новая кнопка **«⬆️ Заменить из файла»** у каждого шаблона — заменяет именно
  этот шаблон картой из JSON (понимает и файл экспорта `{templates:[…]}`,
  и `{currentMap:{…}}`, и одиночный `{grid:…}`).
* Во вкладке «🗺️ Шаблоны карт» добавлена инструкция: загрузить шаблон →
  поправить карту → сохранить под тем же именем (обновление) или «⬆️ Заменить
  из файла».
