# v13.166 — кнопки поворота окопа при расстановке, лимит окопов и расчистки по живым бойцам

Два замечания по инженерным приказам на операционной карте.

**1. Кнопки поворота текстуры окопов были недоступны при расстановке.** Кнопки
«↺ −60° / ↻ +60° / ⟲ Исходный вид» существовали, но их нельзя было нажать, пока в
черновике не выбрана готовая клетка с окопом — а выбрать её было нечем: клик по
клетке в редакторе не подсвечивал её, баннер не перерисовывался. Приходилось
сначала выполнить приказ и только потом «крутить» уже стоящий окоп.

**2. Число окопов и расчистки не ограничивалось.** Правило «не больше числа
отрядов» существовало в черновике, но не работало: в `beginPendingHexEditDraft`
поле `limit` заполнялось **объектом** `{kind, limit, unitName}` вместо числа,
поэтому сравнение «отмечено ≥ лимита» всегда было ложным и окопов можно было
поставить сколько угодно кликов. Новая норма — **по живым бойцам**.

## Что изменилось

### п.1 — поворот окопа в черновике

* `hexEditClick`: если открыт черновик приказа
  (`hexEditorState.draftMode` либо `pendingHexEditDraftActive(hexKey)`),
  клик по карте гекса **всегда** уходит в редактор черновика, а не в выбор
  готового юнита;
* `recordPendingHexEditClick` зовёт `showHexEditorBanner()` внутри `showInfo`,
  поэтому баннер (и блок «🔄 Поворот окопа») перерисовывается сразу после клика:
  клетка подсвечена, кнопки поворота активны;
* `hexEditSelectedTrenchCell` ищет выбранную клетку в трёх местах по порядку:
  черновик → overlay (`hexEdits` / `hexRotations`) → сетка карты
  (`appData.map.grid[cell].type === 'trenches'`). Раньше смотрел только overlay,
  где при расстановке ещё ничего нет;
* `rotateSelectedHex` (index.html) для клетки, отмеченной **только в черновике**,
  пишет угол в `draft.rotations` и **не трогает** `overlay.hexRotations`:
  карта операции не «пачкается» до выполнения приказа, а после выполнения окоп
  появляется уже повёрнутым (угол переносится в overlay вместе с клетками).

### п.2 — лимит по живым бойцам

| Отряд | Норма | Пример |
|---|---|---|
| Обычный | 8 живых бойцов → 1 гекс | 27 → 3, 20 → 2, 9 → 1, 6 → 0 |
| Сапёрный | 5 живых бойцов → 1 гекс | 14 → 2, 7 → 1 |

* константы `HEX_EDIT_FIGHTERS_PER_TRENCH = 8`,
  `HEX_EDIT_FIGHTERS_PER_TRENCH_SAPPER = 5`;
* `hexEditLiveFighters(unit)` — сумма живых бойцов (`hp > 0`, без уничтоженных)
  по всем отделениям отряда;
* `hexEditUnitIsSapper(unit)` — `unit.type === 'engineer_platoon'` **или**
  `/сап[её]р/i` в названии отряда/отделения;
* `hexEditDigHexLimitForUnit(unit) = max(0, floor(живых / (сапёр ? 5 : 8)))`;
* одна и та же норма — и для `dig_in` (окопы), и для `prep_positions`
  (расчистка местности);
* `beginPendingHexEditDraft` хранит `limit` **числом** плюс `limitFighters` и
  `limitPerHex` для подписи; `draftLimitNumber(draft)` понимает и старые сейвы,
  где `limit` был объектом;
* `countSquadsForHexEdit(unit)` теперь возвращает число гексов по живым бойцам
  (а не число отделений c минимумом 1) — им пользуется выдача очков в
  `index.html`;
* `grantTrenchPoints` / `grantPrepPoints`:
  `granted = max(0, (n − уже отмечено в черновике) − выдано ранее)`. Повторный
  приказ на том же гексе больше не накапливает правки сверх лимита;
* в баннере редактора строка «📐 Лимит по приказу: N … (X живых бойцов ÷ 8)»,
  в подсказке `hexEditRuleFor` — «8 бойцов = 1 гекс, у сапёров 5»;
* ноль живых бойцов (или меньше нормы) — приказ окопов не даёт очков.
