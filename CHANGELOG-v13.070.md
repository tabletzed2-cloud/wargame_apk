# v13.070 — надёжное обновление сборки: «новый номер версии, старый код» больше не возможен

Дата: 2026-10-07. Версия отмечена в `index.html` (`APP_VERSION`, заголовок, шапка,
бейдж), `manifest.json` («БМ v13.070») и `service-worker.js`
(`CACHE_NAME = 'wargame-v13.070'`).

## Что случилось (R49)

При проверке v13.069 на устройстве игрока обнаружились две «ошибки», которых в
коде v13.069 нет:

1. **«нет отдельного юнита взвода снабжения»** — юнита не было ни в списке
   батальона, ни на карте;
2. **мастер расстановки ДОТов требовал ровно 5 гексов** вместо «по одному на
   каждый ДОТ».

Оба симптома — это поведение **старой сборки** (взвод снабжения появился только
в v13.068, а «строго 5 гексов» — в v13.065; в v13.066 число гексов стало равным
числу ДОТов). При этом в меню был показан **новый** номер версии (v13.069) —
то есть `index.html` загрузился свежий, а модули `js/*.js` — из старого кэша.

**Причина** — кэш сервис-воркера:

* GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`, а сервис-воркер
  кэширует их «навсегда» (cache-first: `cache.match()` → отдать, иначе сеть);
* при установке новой версии SW ядро кэшировалось обычным `cache.add()` /
  `cache.addAll()`, которые **используют HTTP-кэш браузера**. Если в «тёплом»
  HTTP-кэше лежали старые `js/data.js` / `js/hexmaps.js` / `js/templates.js`, они
  попадали в кэш **новой** версии. После этого устройство навсегда получало
  новую обёртку и старый код: кнопка «🔄 Обновить игру» не помогала — файлы
  `service-worker.js` не менялись, значит переустановки SW и очистки кэша не
  происходило.

## Что сделано

### 1. Предзагрузка ядра в обход HTTP-кэша (`service-worker.js`)

* `precacheCore()` кэширует файлы ядра через
  `cache.add(new Request(url, { cache: 'reload' }))` — браузер обязан взять их
  **из сети**, HTTP-кэш не используется;
* кэш текущей версии перед сборкой удаляется
  (`caches.delete(CACHE_NAME)` → `caches.open(CACHE_NAME)`), поэтому неполный
  или смешанный кэш не «доживает» до активации;
* активный SW по-прежнему удаляет все прочие кэши (`activate`) и сразу
  перехватывает управление (`skipWaiting` + `clients.claim`).

### 2. Проверка версии файлов в кэше перед активацией

* в модули ядра добавлен маркер первой строкой:
  `// ⚡ BUILD-МАРКЕР: v13.070 — синхронизируется с APP_VERSION …`
  (`js/data.js`, `js/hexmaps.js`, `js/templates.js`);
* SW выводит версию из имени кэша (`CACHE_VERSION`) и после предзагрузки
  проверяет `MARKED_ASSETS`: `index.html` — по строке
  `var APP_VERSION = 'v13.070';`, модули — по маркеру;
* если в кэш попал файл другой версии, **установка отменяется** (кэш удаляется,
  SW не активируется) — версия со «чужими» файлами больше не может стать
  активной. Браузер повторит установку при следующей проверке обновления.

### 3. Самопроверка сборки при запуске (`index.html`)

* после загрузки страницы `verifyBuildFreshness()` запрашивает модули ядра
  с `cache: 'no-store'` и уникальным `?build=<APP_VERSION>` (такой URL не
  попадает в кэш SW) и сверяет маркер сборки;
* при несовпадении выполняется **глубокое обновление** `forceDeepUpdate()`:
  снимаются регистрации service worker, удаляются **все** кэши и страница один
  раз перезагружается с параметром `_build=<время>` (обход кэша браузера);
* защита от цикла: глубокое обновление выполняется не более одного раза за
  сессию на версию (флаг в `sessionStorage`); статус виден в строке
  `#appUpdateStatus` под кнопкой обновления; при отсутствии сети проверка
  ничего не меняет.

## Что делать игроку

Обычно ничего: при первом запуске v13.070 сервис-воркер заменится, кэш
пересоберётся в обход HTTP-кэша, и игра покажет правильный состав батальона и
правильное число гексов под ДОТы. Если хотите ускорить — нажмите в главном меню
**«🔄 Обновить игру (свежая версия)»**. Если устройство всё ещё показывает
старое поведение, поможет однократная очистка данных сайта
(в браузере: «Настройки сайта» → «Удалить данные» / в DevTools:
Application → Storage → Clear site data) — после этого страница загрузится
целиком из сети.

защиту от цикла глубокого обновления, а также срабатывание глубокого
обновления на устаревшем модуле и молчание на свежей сборке.

Заодно тест версии из `regression_v13069.js` переведён на сверку
**согласованности** версий (`APP_VERSION` ↔ манифест ↔ имя кэша) вместо
жёсткого «ровно v13.069» — иначе он ломался бы при каждом следующем релизе.

## Не вошло в эту версию

* Отдельная кнопка «Проверить сборку» в меню (проверка выполняется
  автоматически при запуске).
* Принудительная перезагрузка всех открытых вкладок после обновления SW
  (каждая вкладка обновляется сама при следующем запуске).
